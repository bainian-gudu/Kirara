# 界面复刻 refactor/v0.5.2 外观，逐文件明细只记日志

Status: implemented

## Problem

旧分支 `refactor/v0.5.2` 的外观是本项目对外界面的基准：它的布局、字号、间距、边框、
卡片与弹窗骨架来自 `src/index.css`、`src/App.vue`、`src/Dialog.vue`，与当前界面在
步骤表方向、取消按钮尺寸、协议正文卡片和若干间距上不一致，同一个安装包在旧版本与
当前版本里长得不一样。

进度页同时要收敛信息量：逐文件检验明细占满一列且只对排查有用，界面需要的是总体字节量
与速度。明细与外观同属进度块一处布局，一起改才能一次量准窗口高度。

## Decision

### 外观取值来源

`web/layout.css` 的每条规则取 `refactor/v0.5.2` 对应规则的值：

| 位置 | 现值 |
| --- | --- |
| `.step-desc` / `.substep` | 四步竖排，`padding: 14px 10px`、字号 14px、间距 8px、图标 16px；已完成项 13px、`opacity: .8` |
| `.progress` | `flex: 1 1 auto; min-height: 0; overflow-y: auto`，`padding-bottom: 44px` 给浮动取消按钮留出条带；滚动条隐藏 |
| 取消按钮 | `.btn-install` 的通用值：40px 高、距底 20px、宽 140px，进度页不做特例 |
| `.current-status` | 12px、`opacity: .7`、左内边距 14px、上外边距 −6px、等宽字体族 |
| `.finish-text` | `padding: 38px 10px`、18px、图标 24px |
| `.dialog` / `.dialog-footer` | 弹窗自身无内边距；footer `padding: 6px 8px 10px`，按钮为 28px 的静态小按钮 |
| `.agreement-body` | 正文卡片：`padding: 10px 12px`、`margin: 8px 0 4px`、行高 1.8、1px 边框、`--colorNeutralBackground2` 浅底、4px 圆角；h2–h6 为 13.5px/600、段落与列表下边距 8px、引用块 3px 品牌色左边框、`pre` 8px 10px 内边距、`hr` 1px 分隔线、行内 `code` 12px 等宽、链接用 `--colorBrandForegroundLink` |
| `.agreement-link` / `.agreement-link-off` | 下划线 + `text-underline-offset: 2px` / 不可点击的纯文字 |
| `.cdk-input` | `margin: 30px 10px; margin-bottom: 48px` |
| `.read` / `.lnk` / `.more` | 不换行、不截断；路径与源名按原样显示 |

协议弹窗在标题下有说明行，文案键 `dialog.agreement_hint`（中文
`请在使用 {title} 前完整阅读以下条款。`），`{title}` 取 `ui.project.title`，由
`AgreementPanel` 的 `product` 属性传入。取消按钮、多语言、插件面板、协议内联与净化、
接受门槛不受本次改动影响。

### 进度页只留总体统计

状态行单行省略，全文放在 `title`；统计行显示 `12.0MB / 40.0MB (3.0MB/s)`，即总体完成量、
总量与当前速度，速度随阶段在网络接收速度与文件处理速度之间选择。步骤表、统计与进度条
固定不动，`.progress` 只在自身装不下时整块滚动，且不显示滚动条。

### 逐文件明细改为日志

状态结构里没有逐文件条目：`Progress.files`、`FileProgress`、`ByteProgress` 不存在，
`FileAction` 保留——执行侧的 IPC 快照（`ipc/file_progress.rs` 的 `Snapshot` 与
`Reporter`）用它表达当前动作。`ProgressHandle` 在动作切换与任务完成时各写一行 INFO
日志，形如 `[assets/app.exe] verify` 或 `[game-1.0.0.pak] download done 12.0MB / 20.0MB`，
字节后缀由 `byte_suffix` 按 `format_size` 格式化。native 路径的进度对话框读同一份状态，
两个渲染器的语义保持一致。

## Alternatives considered

- 保持 520×250，只让进度块滚动：竖排步骤表加两行状态再加浮动按钮需要 180px，容器只有
  165px，量到 8 处文本行压在取消按钮上。窗口保持 520×280。
- 保留 32px 取消按钮与横排步骤表：那是为 520×250 做的适配，与本次复刻的外观冲突。
- 恢复旧版的 4px 滚动条：与已定的「只滚动、不提供导航条」冲突。
- 明细留在界面但默认折叠：折叠仍会把明细留在状态结构与传输里，界面占位也只是变小。
- 删除 `FileAction`：执行侧快照与日志行都用它，删掉会让日志失去动作语义。

## Verification

测量条件：`dist/index.html` 由 rsbuild 1.5.10 production 构建产出，在
chrome-headless 155.0.8059.79 中以 520×280 与 520×250 两个视口加载；WebView2 宿主桥与
i18n 表按 `web/__tests__/setup.ts` 的同一份合并表注入，界面状态经 `ui-state` 事件推送。
重叠检测取 `.step-desc` 与 `.current-status` 的文本行矩形与取消按钮矩形求交。

| 判据 | 结果 |
| --- | --- |
| 520×280 下文本行不压到取消按钮 | PASS：`running`、`runningStep3`（step 3 + 运行库长名）、`runningLongStatus`（超长路径）三种夹具重叠数均为 0，`document.documentElement.scrollHeight` 恒为 280，`.progress` 的 `scrollHeight` 与 `clientHeight` 同为 195，进度条恒在 276..280 |
| 520×250 装不下竖排步骤表 | 确认下限：`runningStep3` 与 `runningLongStatus` 各 8 处重叠，`.progress` 的 `scrollHeight` 180 大于 `clientHeight` 165；`running` 无重叠但已无余量 |
| 界面不渲染逐文件明细 | PASS：`queryByTitle('assets/app.exe')` 与 `queryByText('校验')` 均为 null，`getByText('1KB / 2KB')` 存在 |
| 协议弹窗 | PASS：520×280 下 `.dialog` 为 4..280 / 16..504，说明行 45..67，正文卡片 75..232 带边框与浅底，footer 236..280 |
| 文案表两语言键集一致且无 `file_action.*` | PASS：`cut -f1` 逐行比对相同，两个文件各 155 行；`native/utils/i18n.rs::every_locale_has_the_same_keys_as_zh_cn` 与 `web/__tests__/i18n-keys.test.ts` 通过 |
| 前端门禁 | PASS：`pnpm exec tsc --noEmit` 无输出；`pnpm test` 41 用例全绿；`pnpm exec rsbuild build` 产出 90,280 字节 `dist/index.html` |
| Rust 类型检查 | PASS：`cargo check --target x86_64-pc-windows-msvc --all-targets` 退出码 0、无 error（假 `cl.exe` / `lib.exe` 只建产物占位，位于 `/tmp`） |
| 快速检查门禁 | PASS：`tools/devcheck/devcheck.ps1` 七层通过，rust 层因缺 MSVC 跳过 |

## Consequences

- 逐文件明细只出现在 `%TEMP%\KachinaInstaller.log` 与控制台，用户要按文件名排查得看日志；
  界面只剩总体字节量与速度。
- 520×280 是复刻外观后的下限：竖排步骤表占 116px，比横排多约 66px。
- 隐藏滚动条与旧版的 4px 滚动条是有意保留的偏差，改回可见滚动条会让 `.progress` 的
  可用宽度少 4px。
- `.progress` 的 `padding-bottom: 44px` 等于浮动取消按钮占用的条带（按钮高 40 + 距底 20
  − `.right` 内边距 16），去掉它会让 step 3 的长状态行压到按钮上。
- 状态行被限制为单行，超长路径与运行库名以省略号截断，全文只在 `title` 提示里可读。
- 真实 WebView2 的滚动条宽度、系统文本缩放下的换行与 DPI 取整仍需在目标机器上确认；
  本机证据来自 headless Chromium。
