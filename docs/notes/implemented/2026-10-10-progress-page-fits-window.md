# 进度页在固定窗口内收敛

Status: implemented

## Problem

安装、更新与卸载共用同一个窗口，客户区大小由宿主写死并按系统文本缩放与 DPI 取整。主容器按内容长高时，进度页比 520×250 客户区的可用高度多出 70 到 130 像素：左栏插画随行高重新适配，右下角取消按钮被推出可视区，进度条压住内容最后一行，看起来像窗口在安装过程中被撑大又恢复。

## Decision

窗口客户区是 520×280，再乘系统文本缩放与 DPI 取整；尺寸只在 `native/host/mod.rs` 定义一处。安装器、更新器与卸载器共用这份宿主代码，卸载器还是安装器映像的副本，三者尺寸必然一致。

主容器 `.main` 与 `.content` 固定为视口高度并 `overflow: hidden`，窗口高度不随内容变化；`.content` 是横向 flex 行，左栏插画在固定列宽内按 `object-fit: contain` 等比缩放。

进度块 `.progress` 占满 `.right` 的剩余高度，步骤表、阶段状态与总体统计固定不动，`.progress` 自身保留 `overflow-y: auto` 兜底：内容自己就装不下时整块滚动，而不是裁掉内容。它的下内边距是 44px，等于浮动取消按钮占用的条带（按钮高 40 + 距底 20 − `.right` 内边距 16），正文整体落在按钮上方，任何一行都不会被按钮遮挡。

滚动区不显示滚动条（`scrollbar-width: none` 与 `::-webkit-scrollbar { display: none }`），内容超出时用滚轮查看。

进度页的内容量与外观取值见[界面复刻 refactor/v0.5.2 外观，逐文件明细只记日志](./2026-10-15-ui-matches-v052.md)：四步竖排的步骤表占 116px，逐文件明细不再进界面，界面只保留总体字节量与速度。

## Alternatives considered

- 保持 520×250，只让整个进度块滚动：容器只有 165px，竖排步骤表加两行状态再加浮动取消按钮需要 180px，量到 8 处文本行压在按钮上。
- 加高到 300 以上以容纳竖排步骤表：确认页内容只到 194.7px，多出的高度成为空白，左栏插画在更高的列里显得更小。
- 安装期间隐藏产品描述行：省下 32.8px，但确认页与进度页之间会出现内容跳动，长描述下也不够用。
- 把可滚内容拆成多个固定高度的滚动区：每个区域都要各自处理与取消按钮的间距，且滚动位置互不相干。

## Verification

测量条件：`dist/index.html` 由 rsbuild 1.5.10 production 构建产出，在 chrome-headless-shell 155.0.8059.39 中以 520×280 与 650×350 两个视口加载；WebView2 宿主桥与 i18n 表按 `web/__tests__/setup.ts` 的同一份合并表以脚本注入，界面状态经 `ui-state` 事件推送。

| 判据 | 结果 |
| --- | --- |
| 主容器高度恒等于视口，不随进度内容变化 | PASS：确认页、进度页、完成页、失败页与弹窗各夹具下 `document.documentElement.scrollHeight` 与 `.content` 高度都等于视口高度；未收敛前同一条件下量到 271（step 2）与 380.7（step 3 + 12 个文件） |
| 左栏插画不被拉伸，取消按钮与进度条始终在窗口内 | PASS：插画容器恒为 168×226；取消按钮 236..268、进度条 276..280，滚动前后位置不变 |
| 步骤表、统计与进度条不随滚动移动 | PASS：`.progress` 自身滚动量为 0 时三者的矩形位置不变 |
| 文本行不与浮动取消按钮重叠 | PASS：520×280 下 `running`、`runningStep3`、`runningLongStatus` 三种夹具的重叠数均为 0，`.progress` 的 `scrollHeight` 与 `clientHeight` 同为 195 |
| 内容超出时可滚动查看且不出现滚动条 | PASS：520×250 下 `.progress` 的 `scrollHeight` 180 大于 `clientHeight` 165，滚到底后内容末行位于取消按钮上方；`offsetWidth - clientWidth` 为 0，滚动条不占宽度 |

## Consequences

- 520×280 是进度页的下限：520×250 下竖排步骤表加两行状态再加浮动按钮需要 180px，容器只有 165px，量到 8 处文本行压在取消按钮上。
- 真实 WebView2 的滚动条宽度、系统文本缩放下的步骤表换行与 DPI 取整仍需在目标机器上确认；本机证据来自 headless Chromium。
